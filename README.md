# ZAG Flow

ZAG Flow принимает заявки на автоматизацию и помогает сотруднику определить порядок их разбора. Посетитель выбирает услугу и бюджет, описывает задачу и оставляет контакт. В панели управления доступны каталог услуг, заявки с объяснением приоритета и анонимная статистика посещений.

[Адрес сайта при проверке](https://186.246.28.195/next/) · [Панель при проверке](https://186.246.28.195/next/admin.html) · [API при проверке](https://186.246.28.195/next/api/docs)

**Онлайн-демонстрация отключена 22 октября 2026 года.** VPS и его публичный IP удалены. Адреса выше приведены только для сопоставления со скриншотами; действующий сайт по ним не предоставляется. [Статус демонстрации](docs/DEMO_STATUS.md). Проверить проект можно локально по инструкции ниже.

Демонстрация предназначена для вымышленных данных. При серверной проверке версия 0.2.0 была сохранена отдельно по [корневому адресу](https://186.246.28.195/).

## Возможности

- пошаговая форма, каталог услуг и бюджет в допустимом диапазоне;
- проверка входных данных и сохранение заявок в PostgreSQL;
- первичная регистрация администратора, scrypt-хеш пароля и JWT сроком на час;
- создание, редактирование и удаление услуг через таблицу;
- защита истории: использованная в заявке услуга не удаляется;
- список обращений, карточка с контактами, баллом и объяснением приоритета;
- секундный сбор активного времени, кликов и нормализованных координат;
- среднее время за 24 часа, 7 и 30 дней без многократного учёта одного посещения;
- карта последних 2000 снимков курсора и сводка нажатий;
- HTTPS с доверенным сертификатом на IP и автоматическим продлением;
- отдельные контейнеры и база новой версии, без замены прежнего сайта.

Формула оценки и её ограничения описаны в [PRIORITY_RULES.md](docs/PRIORITY_RULES.md). Внешняя языковая модель не используется. Отправка писем и сообщений автоматически не выполняется.

## Архитектура

```text
HTTPS Nginx на 443
  /       -> сохранённый Frontend -> сохранённый API -> прежняя PostgreSQL
  /next/  -> новый Frontend       -> новый API       -> отдельная PostgreSQL
```

Новый контур задаётся файлом compose.admin.yml и именем проекта zag-flow-admin. Backend и PostgreSQL не публикуют порты на хосте. Временный pgAdmin включается только профилем tools и доступен через localhost/SSH-туннель. Registry в новом контуре отсутствует.

При серверной проверке новая версия была размещена в /opt/zag-flow-admin с COMPOSE_FILE=compose.admin.yml в .env. Версия 0.2.0 находилась в /opt/zag-flow; её файлы и база не заменялись новой версией.

## Локальный запуск с Docker

Нужны Python 3.12+, Node.js 22+ для отдельной сборки и работающий Docker Compose.

1. Скопировать .env.example в .env. Задать разные случайные значения POSTGRES_PASSWORD, SECRET_KEY, SERVICE_ADMIN_TOKEN и PGADMIN_DEFAULT_PASSWORD. SECRET_KEY должен содержать не менее 32 байт. Секреты не публиковать.
2. Для локального запуска добавить в .env PUBLIC_BASE_PATH= с пустым значением.
3. Создать общую сеть командой docker network create zag-flow_edge, если она ещё не существует. Существующую сеть не пересоздавать.
4. Запустить отдельный контур:

```powershell
docker compose -f compose.admin.yml -f compose.local.yml config --quiet
docker compose -f compose.admin.yml -f compose.local.yml up -d --build --wait
```

Сайт: http://127.0.0.1:8081/, панель: http://127.0.0.1:8081/admin.html, API: http://127.0.0.1:8081/api/docs. Локальный HTTP привязан только к loopback. Новая база изначально пустая.

Первый администратор вводит свой логин, пароль и одноразовый SERVICE_ADMIN_TOKEN. Сам SECRET_KEY в браузер не передаётся. После создания администратора повторная регистрация блокируется сервером. JWT хранится в памяти вкладки; обновление страницы требует повторного входа.

Остановка локального контура без удаления данных:

```powershell
docker compose -f compose.admin.yml -f compose.local.yml down
```

Файл docker-compose.yml сохраняет исходную инфраструктуру и не используется для нового контура. На VPS нужен PUBLIC_BASE_PATH=/next и дополнительный маршрут из deployment/https/nginx/default.conf; сертификаты подключены только к внешнему HTTPS Nginx.

## Автоматические тесты

В виртуальном окружении:

```powershell
python -m pip install -r backend/requirements-dev.txt
$env:PYTHONPATH = 'backend'
python -m pytest backend/tests -q
```

Без POSTGRES_TEST_URL интеграционная проверка PostgreSQL пропускается. Остальные проверки используют временные SQLite-базы. Интеграционный сценарий допускает только отдельную базу zag_flow_admin_check; адрес рабочей базы в тесты не передаётся. DEMO_SQL_PATH должен указывать на docs/sql/demo-requests.sql.

Отдельная сборка Frontend:

```powershell
npm --prefix frontend run build
```

PUBLIC_BASE_PATH задаёт префикс путей при сборке. Сборка создаёт index.html, admin.html и CSS/JavaScript с хешами. Дополнительные npm-пакеты не нужны.

## API

| Метод и путь | Назначение |
|---|---|
| GET /api/health | Состояние API и базы |
| GET /api/auth/check | Доступность первичной регистрации |
| POST /api/auth/register | Первое создание администратора с ключом настройки |
| POST /api/auth/login | JWT для входа |
| GET /api/auth/me | Профиль, требуется JWT |
| GET /api/services | Публичный каталог |
| POST /api/services | Создание услуги, JWT |
| PUT /api/services/{id} | Изменение услуги, JWT |
| DELETE /api/services/{id} | Удаление свободной услуги, JWT |
| POST /api/requests | Отправка формы |
| GET /api/requests | Приоритеты и страницы списка, JWT |
| GET /api/requests/{id} | Детальная карточка, JWT |
| GET /api/requests/{id}/status | Только технический статус без контактов |
| POST /api/behavior-metrics | Анонимный секундный снимок |
| GET /api/behavior-metrics | Агрегированная статистика, JWT |

В публичном новом контуре ко всем путям добавляется /next. В Swagger для Authorize используется JWT, а не ключ первичной настройки.

## Демонстрационные данные

В docs/sql/demo-requests.sql подготовлены десять вымышленных заявок: 4 высокого, 3 среднего и 3 низкого приоритета. Повторный запуск не создаёт дубли. Все заявки имеют технический статус new; ожидаемые баллы вынесены в expected-priorities.json. SQL для таблицы администратора — admin-schema.sql; обычный запуск приложения создаёт её автоматически.

## Границы демонстрации

Содержимое полей формы не передаётся в метрики. Посетитель видит уведомление о сборе времени, кликов и координат; постоянный идентификатор человека и технический отпечаток устройства не создаются.

До использования реальных персональных данных необходимы политика обработки, сроки хранения и порядок удаления. Текущая демонстрация использует вымышленные данные. Ранжирование основано на явных правилах, а карта показывает ограниченную выборку снимков.
