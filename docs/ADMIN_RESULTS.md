# Проверки панели управления ZAG Flow

22 октября 2026 года проверил API, интерфейс и отдельное развёртывание версии 0.3.0.
Результаты ниже относятся к этой дате. [Статус онлайн-демонстрации](DEMO_STATUS.md).

## Автоматические проверки

Окончательный набор на Ubuntu с Python 3.12 и отдельной временной PostgreSQL 16:

```text
....................                                                     [100%]
20 passed in 7.15s
```

В этом запуске прошли как изолированные проверки с SQLite, так и интеграционный
сценарий с PostgreSQL. Тестовая PostgreSQL работала в отдельном контейнере без
публичного порта; после проверки удалил тестовые контейнеры и их сеть.
Рабочие базы сайта в тестах не использовал.

Проверил:

- создание только одного администратора при одновременной регистрации;
- исчезновение доступности повторной регистрации на уровне API;
- отказ при неверном ключе первичной настройки, логине или пароле;
- хранение scrypt-хеша вместо пароля;
- вход после повторного запуска приложения с той же базой;
- отказ для повреждённого, просроченного JWT, неверной подписи и отсутствующего exp;
- отсутствие доступа со старым служебным ключом вместо JWT;
- защиту чтения заявок, статистики и изменения каталога;
- создание, изменение и удаление услуги, диапазоны бюджета и уникальность названия;
- сохранение заявки и запрет удаления услуги, на которую она ссылается;
- отсутствие дублирования метрик при повторной отправке;
- среднее время по двум посещениям, а не по числу секундных снимков;
- корректный выбор последнего sequence при приходе снимков не по порядку;
- отдельные периоды 24 часа, 7 и 30 дней;
- отбрасывание координат вне диапазона 0–1;
- десять заявок с категориями 4/3/3, сортировку и разбиение на страницы;
- неизменность результата приоритета от технического статуса new;
- повторную загрузку PostgreSQL SQL-набора без дублирования заявок;
- Swagger за префиксом /next и Cache-Control: no-store для закрытых данных.

Проверил синтаксис JavaScript и выполнил npm run build. Сборка создала отдельную
страницу управления, общий CSS и файлы JavaScript с хешами в именах.

Docker-сборку Backend и Frontend, конфигурации Compose и Nginx проверил
на VPS в отдельном контуре. Локальную сборку контейнеров не выполнял:
Docker Engine на рабочем компьютере был недоступен.

## Проверка интерфейса

На временной локальной базе через браузер создал администратора и вошёл в панель.
Создал услугу, изменил её название и верхнюю границу бюджета. Обновлённые значения
появились в таблице и каталоге главной страницы.

В списке десяти демонстрационных заявок получил четыре высоких, три средних и
три низких приоритета. В карточке Максима увидел 70 баллов: 50 за срочный срок
и 20 за описанные потери.

На главной странице записались метрики посещения, нажатие на кнопку и координаты.
Панель показала одно посещение со средним и максимальным временем 315 секунд,
315 секундных снимков и 66 точек курсора на момент просмотра. Совпадение среднего
за три периода было корректным: все данные получены в один день.

Затем выполнил ручной сценарий на публичной версии: создал пять услуг через
панель, изменил название и бюджет одной из них, удалил свободную услугу и
проверил её исчезновение из списка на главной странице после обновления.
Создал администратора denis_admin; после выхода кнопка регистрации исчезла.
В Swagger запрос профиля вернул 200 и логин без раскрытия токена в кадре.

После работы с главной страницей статистика показала три посещения со средним
временем 276,3 секунды и максимумом 418 секунд. На момент снимка карта содержала
821 точку по 830 секундным записям. В pgAdmin подтвердил сохранение времени,
кликов и координат: в последних десяти строках было от 409 до 418 секунд и
накопленный счётчик восьми кликов. Эти восемь кликов относятся к посещению,
а не суммируются заново для каждой секундной записи.

Загрузил SQL-набор в отдельную базу zag_flow_admin. В панели получил десять
заявок и категории 4/3/3. В карточках Максима и Виктора проверил 70 и 0 баллов,
исходные данные и причины оценки. Запрос карточки средней заявки также есть
в проверенном фрагменте журнала с ответом 200.

Изображения сохранены в docs/images/3/A01…A14; описание результатов —
в [DEMONSTRATION.md](DEMONSTRATION.md).
Временный локальный сервер после проверки остановил.

## Отдельное развёртывание

Новая версия находится в /opt/zag-flow-admin, Compose-проект zag-flow-admin,
база zag_flow_admin, отдельный том zag-flow-admin_postgres_data.
На момент проверки работают frontend, backend и postgres, все healthy.
pgAdmin нового контура выключен по умолчанию; Registry в нём не создаётся.
Ни один из этих контейнеров не публикует порт напрямую в интернет.

Внешние проверки:

| Адрес / проверка | Результат |
|---|---|
| /next/admin.html | 200, страница входа с первичной регистрацией |
| /next/api/health | 200, status=ok, database=ok |
| /next/api/auth/check при первом запуске | registration_available=true; после регистрации кнопка исчезла |
| /next/api/requests без JWT | 401 |
| /next/v2/ | 404 |
| /api/openapi.json | Сохранённая версия 0.2.0 |
| /next/api/openapi.json | Новая версия 0.3.0 |
| Главная по прежнему адресу | SHA-256 совпал до и после подключения /next/ |

После ручной проверки администратор, каталог и десять демонстрационных заявок
сохранены в новой базе. Во время первичного развёртывания база была пустой;
регистрацию и загрузку данных выполнил отдельно через интерфейс и pgAdmin.

В конце остановил только pgAdmin нового контура. Снимок A14 подтверждает три
основных сервиса со статусом healthy и успешный nginx -t. В последних 30 строках
Backend запросы входа, профиля, каталога, списка и трёх карточек заявок получили
200 OK; строки health-check тоже завершились с 200. Ошибок в этом фрагменте нет.
Это описание конкретного фрагмента, а не утверждение об отсутствии ошибок за
всё время работы сервера.

## Ограничения

При первом включении профиля tools pgAdmin запустился без работающего
проброса localhost:5051: контейнер был подключён только к сети internal.
Добавил отдельную bridge-сеть tools исключительно для pgAdmin и пересоздал
только этот контейнер с прежним томом данных. После исправления порт слушает
127.0.0.1:5051; HTTP-страницу входа проверил отдельно. Backend и PostgreSQL
при этом не перезапускал.

Приоритет основан на ключевых словах, бюджете и полноте описания. Это объяснимая
эвристика, а не анализ произвольного текста языковой моделью. Карта курсора
показывает последние 2000 снимков, а не неограниченную историю за месяц.

При проверке сохранённая версия работала в своём контуре. Общий список
контейнеров VPS включал её pgAdmin и Registry; эти сервисы не относятся
к новой панели. Состояние новой версии проверил командой docker compose ps
из /opt/zag-flow-admin.
