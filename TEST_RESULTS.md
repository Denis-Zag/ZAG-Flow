22 октября 2026 года проверил панель управления, JWT, каталог, метрики,
приоритеты и отдельное развёртывание. Окончательный запуск с PostgreSQL:
**20 passed in 7.15s**. Детальные результаты и границы ручной проверки —
в [ADMIN_RESULTS.md](docs/ADMIN_RESULTS.md).

Ручной сценарий завершён: первичная регистрация и JWT-профиль, пять созданных
услуг, изменение и удаление с проверкой публичного списка, статистика и записи
метрик в PostgreSQL, десять заявок с распределением 4/3/3, подробные карточки.
В конце pgAdmin новой версии остановлен; основные сервисы healthy,
nginx -t успешен. В проверенных последних 30 строках Backend видны ответы 200,
ошибок в этом фрагменте нет. Изображения — в [DEMONSTRATION.md](docs/DEMONSTRATION.md).

Ниже сохранены результаты проверки прежней версии 0.2.0, которая при проверке
работала с отдельной базой. [Статус онлайн-демонстрации](docs/DEMO_STATUS.md).

Дата проверки: 21 октября 2026 года. Использовал только вымышленные данные.

При развёртывании сборка `npm run build` была выполнена внутри Docker-образа. Имена файлов содержат хеш содержимого, поэтому изменённые CSS и JavaScript получают новые адреса.

## Серверный контур

Timeweb Cloud, Ubuntu 24.04 LTS amd64, 2 vCPU, 4 ГБ RAM, диск 30 ГБ и 2 ГБ swap.

Повторно проверил шесть сервисов Docker Compose:

- Frontend/Nginx, Backend, PostgreSQL и Watchtower — `healthy`;
- pgAdmin и Registry — `Up`.

`nginx -t` подтвердил корректность конфигурации. `/api/health` вернул `200` и `{"status":"ok","database":"ok"}`.

Перед обновлением сохранил резервную копию исходников и базы. Существующие заявки не удалялись, при обновлении схемы к ним добавилось необязательное поле `service_id`.

Названия услуг описывают предложения в каталоге. Интеграция с Telegram Bot API и отправка сообщений в проекте не реализованы.

## Проверка формы и базы

В новой демонстрации выбрал услугу «Приём и обработка заявок», заполнил данные вымышленной компании «Мастерская Север» и установил бюджет 20 000 ₽. На последнем шаге указал имя Алексей, адрес `demo@example.com` и способ связи Email.

Сначала нажал кнопку отправки без согласия. Форма осталась открытой и показала сообщение об обязательных полях. После установки галочки согласия появилось сообщение «Заявка отправлена!» с номером:

```text
2c51a3be-6048-4507-b19e-efd118cc0738
```

В логе Backend подтверждён `POST /api/requests` с ответом `201 Created`. В pgAdmin выполнил запрос по этому ID; затем повторно проверил запись прямым запросом к PostgreSQL:

```sql
SELECT
    r.id,
    s.name AS service,
    r.budget,
    r.contact_name,
    r.contact_method,
    r.status
FROM automation_requests AS r
JOIN services AS s ON s.id = r.service_id
WHERE r.id = '2c51a3be-6048-4507-b19e-efd118cc0738';
```

```text
id:             2c51a3be-6048-4507-b19e-efd118cc0738
service_id:     1
service:        Приём и обработка заявок
budget:         20000
contact_name:   Алексей
contact_method: Email
status:         new
```

Публичный endpoint `/api/requests/2c51a3be-6048-4507-b19e-efd118cc0738/status` также вернул `200` и статус `new` без контактных данных.

## Обнаруженные проблемы и исправления

- Браузер первоначально показывал сохранённую тёмную страницу. Полное обновление загрузило актуальную светлую версию; сервер отдаёт HTML с `Cache-Control: no-cache`, а CSS/JS имеют хеши в именах.
- После потери SSH-перенаправления pgAdmin перестал открываться на рабочем компьютере. Сам pgAdmin и PostgreSQL на VPS продолжали работать. Подключение восстановил через локальный порт `15050`; запрос к базе выполнился успешно.
- При первом локальном запуске тестов отсутствовал родительский временный каталог. Создал его и повторил проверку: все тесты прошли.

## Границы демонстрации

На момент описанных выше проверок сайт работал по HTTP. Служебный ключ для создания услуг вводился только через localhost по SSH-туннелю. В публичную форму передавались вымышленные данные. 22 октября 2026 года подключён HTTPS без изменения версии приложения; отдельные проверки приведены в [HTTPS_DEPLOYMENT.md](docs/HTTPS_DEPLOYMENT.md).

В версии 0.2.0 способ связи сохранялся в базе для последующей обработки заявки. Автоматической отправки писем, сообщений в Telegram и панели управления в этой версии не было. Панель реализована в версии 0.3.0, описанной в начале отчёта.
